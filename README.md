# Альтус. Сайт и панель управления

ООО «Альтус», рекламно-производственная группа. Производство и монтаж
наружной рекламы и вывесок в Екатеринбурге.

Одно приложение: публичный сайт на корне и админ-панель под `/admin`.
Сайт собирается на сервере из данных админки, отдельного API между ними нет.
Контент, логотип и фотографии перенесены с действующего сайта rg-altus.ru.

| | |
|---|---|
| Сайт | `/`, `/blog`, `/blog/<slug>` |
| Админка | `/admin` (вход `/admin/login`) |
| Демо-витрина прошлого разработчика | `/site`, оставлена как справочник |

---

## Запуск

Нужны PHP 8.1+ (`pdo_mysql`, `fileinfo`, `mbstring`, `dom`) и MySQL 8 или
MariaDB 10.4+. Ни Composer, ни npm, ни сборки.

```bash
cp config/config.example.php config/config.php     # заполнить доступы к БД
mysql -u root -e "CREATE DATABASE altus CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;"
mysql -u root altus < database/schema.sql
php database/seed.php                              # стартовый контент сайта
php database/create_admin.php "Имя" you@example.com пароль-от-10-символов
```

Дальше любой из двух вариантов.

**Боевой сервер.** Docroot строго `public/`. Всё остальное (`app/`, `config/`,
`database/`) лежит выше и наружу не отдаётся. Apache читает `public/.htaccess`
сам; для nginx конфиг есть в `CLAUDE.md`, раздел 8.

**Локально, без Apache.** Встроенный сервер PHP плюс маленький роутер, который
повторяет работу `.htaccess`:

```bash
php -S 127.0.0.1:8000 -t public public/router.php
# сайт    http://127.0.0.1:8000
# админка http://127.0.0.1:8000/admin
```

`public/router.php` нужен только здесь: без него встроенный сервер отдаёт 404
на красивые адреса. На боевом сервере он не используется.

### Что менять в config.php

```php
'base_url'     => 'https://rg-altus.ru',  // без слэша в конце
'admin_prefix' => '/admin',               // адрес закрытой части
'debug'        => false,                  // true только локально
```

`admin_prefix` меняется одной строкой: маршруты, меню, редиректы и формы
админки берут его из `admin_path()`, руками нигде не прописан.

## Как сайт связан с админкой

Страницы собираются на сервере: контроллер берёт строки моделью и отдаёт
готовый HTML. **JSON API между фронтендом и бэкендом намеренно нет.**
`CLAUDE.md` предлагал такой слой, но он писался в расчёте на отдельное
приложение на своём домене (Next, Vite). Здесь сайт и админка это один
проект на одном домене, поэтому server-side проще и лучше: нет CORS,
нет пустых секций до ответа, контент виден поисковику, страница работает
без JavaScript. Скрипты на сайте только улучшают уже готовую страницу.

| Раздел сайта | Таблица | Файл |
|---|---|---|
| Наши услуги | `services` | `app/Views/front/home.php` |
| О нас, полоса фотографий | `about` | там же |
| Наши работы | `works` | там же |
| Видео | `videos` | там же |
| Отзывы | `reviews` | там же |
| Блог, блок на главной | `posts` | там же |
| Блог, список и статья | `posts` | `blog.php`, `post.php` |

Hero, «Ход работы» и «Контакты» свёрстаны в шаблоне: полей под них в базе нет.

### Пустой раздел не показывается

Раздел без строк в базе не выводится вообще, вместе со своим пунктом меню
и в шапке, и в подвале. На свежей установке посетитель видит первый экран,
«Ход работы» и «Контакты», а не вереницу пустых заголовков. Заполнили раздел
в админке — он сам вернулся на сайт. Проверено на пустой базе.

### Договорённости о тексте

В таблицах по одному текстовому полю, а вёрстке нужно больше одного куска.
Текст делится по строкам, и это единственное, что важно знать редактору:

| Что | Как заполнять |
|---|---|
| Услуга, `description` | первый абзац виден всегда, всё после пустой строки уезжает под «Показать полностью» |
| Работа, `description` | строка 1 — название, строка 2 — тип конструкции, дальше — описание, видно в лайтбоксе |
| Отзыв, `author` | строка 1 — имя или компания, строка 2 — должность |

Написали меньше строк — на сайте просто меньше частей, ничего не ломается.
Услуга в один абзац выводится без кнопки «Показать полностью», отзыв в одну
строку — без должности.

### Остальные правила подстановки

* **Цена услуги.** Ноль в базе значит «не указана»: на сайте выводится
  «Цена по запросу» приглушённым стилем. Любое число больше нуля
  форматируется как `84 000,00 ₽`.
* **Скан отзыва.** Картинка открывается в лайтбоксе сайта. PDF лайтбокс
  показать не может, поэтому для PDF это обычная ссылка в новой вкладке.
* **Видео.** Поля под постер в таблице нет, поэтому плиткой стоит сам ролик
  с `preload="metadata"` и якорем `#t=0.5`: браузер тянет только заголовок
  файла и рисует кадр с половины секунды. Первый кадр часто чёрный, поэтому
  не ноль. Появится `poster_path` — в шаблоне достаточно вернуть `<img>`.
* **Размеры картинок.** В базе их нет, поэтому `width` и `height` читаются
  с диска через `getimagesize()` (только заголовок файла) и кешируются на
  запрос. Без них страница дёргается при загрузке.
* **Тело статьи** выводится как есть, без экранирования: оно уже прогнано
  через `HtmlSanitizer` при сохранении. Это единственное такое место на сайте.
  Стили в `.prose` покрывают весь белый список редактора, включая таблицы,
  списки, цитаты и код.
* **Раскладка сеток считается по количеству строк.** Услуги ложатся в сетку
  на 12 колонок, работы — в мозаику на 6. Ряд всегда заполняется целиком
  при любом количестве записей: `services_spans()` и `works_spans()`
  в `app/Core/front_helpers.php`. Проверено от одной записи до одиннадцати.

## Стартовый контент

`php database/seed.php` кладёт в базу то, что сейчас на сайте: девять услуг,
восемь работ, четыре благодарственных письма, три фотографии производства
и три записи блога. Картинки копируются из `database/seed-media`
в `public/uploads`, потому что сам каталог загрузок в git не хранится.

Скрипт идемпотентный: повторный запуск ничего не дублирует и не трогает то,
что уже завели в админке. Услуга узнаётся по названию, работа и фотография
по файлу, отзыв по автору, запись блога по slug.

## Дизайн-система

### Палитра

Взята из логотипа заказчика. Фирменный синий снят пипеткой прямо из файла
логотипа, с шевронов щита: **#2F83FB**. Нейтралы построены на том же тоне
215° с очень низкой насыщенностью, поэтому серый на сайте родственен
логотипу. ТЗ просит синие и тёмные оттенки, это ровно она.

Логотип синий на почти чёрном с белой графикой, поэтому на тёмном сайте он
работает как есть, без перекраски. Фирменный синий проходит по контрасту
и используется акцентом напрямую, без осветления.

Акцент ровно один, залочен на всю страницу. Тема одна, тёмная, секции
не инвертируются.

Сознательное решение: **свечение неона приходит с фотографий, а не из CSS.**
Ни одного blur-glow, неонового ореола и градиентной заливки по тексту.

Весь контраст проверен в браузере на вычисленных цветах, а не на бумаге:
30 пар текст и фон, все проходят WCAG AA, приглушённые цвета проверены
на самой светлой поверхности, где они встречаются.

### Шрифты

* **Unbounded** для заголовков. Широкий геометрический гротеск: буква как
  изделие, что для производителя вывесок уместнее нейтрального шрифта.
* **Onest** для текста и интерфейса.

Оба вариативные, оба с полной кириллицей, оба подключены локально.
Засечных шрифтов на сайте нет.

Кегль заголовка первого экрана ограничен сверху 3.35rem: Unbounded широкий,
и при большем размере заголовок перестаёт помещаться в две строки.

### Форма

Одна шкала скруглений на весь сайт:

| Что | Радиус |
|---|---|
| Поверхности, карточки, медиа | `--r-lg` 16px |
| Кнопки, поля, чипы | `--r-md` 10px |
| Мелкие метки | `--r-sm` 6px |

Скруглений вне шкалы нет, pill-кнопок нет.

### Раскладки

Девять секций, девять непохожих layout-семейств, ни одно не повторяется:

| Раздел | Семейство |
|---|---|
| Первый экран | асимметричный сплит со смещением медиа по вертикали |
| Наши услуги | 12-колоночная сетка, разные пролёты, широкая карточка-скобка |
| Ход работы | липкая колонка слева, вертикальный рельс с этапами справа |
| О нас | полоса фото во всю ширину окна и наезжающая на неё карточка |
| Наши работы | мозаика, ряды 4+2 / 2+4 / 2+4 / 3+3 |
| Видео | равномерная сетка 16 к 9 |
| Отзывы | горизонтальный ряд со scroll-snap |
| Блог | одна крупная запись плюс стопка мелких |
| Контакты | сплит «инфо и форма» плюс карта во всю ширину |

Подряд идущих сплитов «картинка и текст» больше двух не встречается.
Бегущих строк нет ни одной. Мелких капслок-меток над заголовками нет вообще.

### Движение

Каждая анимация отвечает на вопрос «что она сообщает»:

| Что | Зачем |
|---|---|
| Появление первого экрана лесенкой | задаёт порядок чтения в первую секунду |
| Появление секций при скролле | последовательное раскрытие по мере чтения, срабатывает один раз |
| Подъём кнопки на hover, нажатие на active | тактильный отклик |
| Открытие лайтбокса масштабом | переход состояния, связывает миниатюру и полный вид |
| Раскрытие текста услуги | показывает, что блок вырос, а не подменился |
| Спиннер и статусы формы | отклик на отправку |

Скролл нигде не перехватывается. Обработчика `scroll` на `window` нет:
положение шапки и появление блоков считает `IntersectionObserver`.
Всё движение выключается при `prefers-reduced-motion: reduce`.

## Что нужно от заказчика

Содержимое разделов теперь редактируется в админке и правок в коде
не требует. Ниже только то, что осталось заглушкой в самой вёрстке.

### 1. Цены услуг

На старом сайте цен не было, поэтому во всех карточках стоит «Цена по
запросу»: в базе `price` равна нулю. Проставьте числа в админке, разделе
«Наши услуги», и цена сама станет акцентной, править код не нужно.

### 2. Соцсети

Ссылок на соцсети на старом сайте не нашлось. Сейчас в блоке `.socials`
в `app/Views/front/home.php`:

* **ВКонтакте** и **Telegram** стоят заглушкой `href="#"`, нужны ссылки
* **WhatsApp** собран из вашего номера: `https://wa.me/79120454444`.
  Проверьте, что мессенджер на этом номере действительно подключён
* ссылка на политику конфиденциальности стоит как `#`

Телефон, почта, адрес и режим работы в контактах настоящие.

### 3. Блог

Раздел требуется по ТЗ, но на старом сайте его не было, поэтому три записи,
которые кладёт `seed.php`, демонстрационные. Правятся и удаляются в админке,
разделе «Блог», как обычные записи.

### 4. Логотип

Логотип установлен, от заказчика по нему ничего не нужно. Ниже, что было
сделано с присланным файлом, чтобы при следующей замене не гадать.

Исходник `367437847.svg` нарисован под белый фон: холст залит белым
прямоугольником, а поверх лежит белый путь на все 2000×2000, у которого
щит вырезан по правилу evenodd. На тёмной странице это дало бы белый
квадрат вокруг знака.

Прямолинейное решение — выкинуть белый путь целиком — ломает логотип:
надпись «АЛЬТУС», корона и блики на гриве нарисованы **тем же путём**,
отдельными подпутями внутри вырезанного щита. Убрав путь, я получил чёрную
надпись на чёрном щите. Правильный разбор такой: у пути 30 подпутей, нулевой
это холст, первый это контур щита; удалены ровно эти два, остальные 28
(надпись, корона, блики) оставлены. При evenodd они снова оказываются
залитыми и логотип выглядит в точности как в исходнике.

Что лежит в репозитории:

| Файл | Назначение |
| --- | --- |
| `public/assets/img/logo-mark.svg` | вектор без белой подложки, для крупных мест и печати |
| `public/assets/img/logo-mark.png` | 358×372, его грузит страница |
| `public/assets/img/favicon-64.png` | значок вкладки |
| `public/assets/img/favicon-180.png` | значок для домашнего экрана iOS |

Страница грузит PNG, а не вектор, сознательно: в шапке знак высотой 40px,
358px по длинной стороне хватает даже при DPR 3, и PNG весит 15 КБ против
52 КБ у сжатого вектора. Вектор оставлен рядом как оригинал.

Замена знака — это замена одного файла `public/assets/img/logo-mark.png`. Править
HTML не нужно: тег `<img>` стоит на месте во всех пяти страницах. Если файла
не окажется, скрипт уберёт картинку, и в шапке останется наборная надпись
«АЛЬТУС» без иконки битого изображения. Требования к новому файлу: примерно
квадратный, от 240px по стороне, PNG с прозрачностью.

Перекрашивать логотип не пришлось: он синий на почти чёрном, на тёмном фоне
сайта читается как есть. Тёмная середина щита чуть светлее фона страницы,
силуэт держат серый контур и синие шевроны.

Про значок вкладки, честно: на 32px щит и шевроны читаются, на 16px лев
превращается в шум. Я оставил знак заказчика как есть, а не перерисовал его
под мелкий размер. Если 16px важен, нормальный ход — упрощённый герб без
льва и без надписи, одни шевроны; скажите, и сделаю.

### 5. Видео

Роликов пока нет, поэтому раздела на сайте нет: он появится сам, как только
загрузите первый файл в админке, разделе «Видео». Вместе с ним вернётся
и пункт меню.

Берите **MP4 с кодеком H.264**: WebM не играет в Safari. Админка принимает
mp4, webm, ogv и mov, до 512 МБ.

Ссылку на ВК Видео, YouTube или Rutube админка сейчас не принимает, только
файл. Лайтбокс сайта внешний плеер открывать умеет (`data-lb-embed`), так что
если такие ролики понадобятся, на стороне сайта всё готово — нужно поле под
ссылку в таблице `videos`.

### 6. Фото производственного цеха

В разделе «О нас» полоса фотографий: буквы на сборке, монтаж на фасаде
и работа промышленного альпиниста. Это настоящие снимки с вашего сайта,
но исходники всего 300x400 и на широком экране заметно мягкие. Загрузите
фотографии цеха от 1600px по длинной стороне через админку, раздел «О нас»,
и они заменят нынешние. Количество любое: полоса подстраивается.

## Заявки с формы: единственное, что не подключено

Всё остальное на сайте ходит в базу. Контактная форма — нет, и это стоит
прочитать целиком, а не заметить потом.

**Сейчас форма показывает «Заявка отправлена», но никуда её не отправляет.**
Заглушка проходит полный цикл состояний (проверка полей, отправка, успех,
ошибка), и для показа этого достаточно, а для боевого сайта — нет.

Причина не в лени: в админке **нет таблицы под заявки**. В модели данных
`CLAUDE.md` их нет вообще — там только контент: услуги, работы, отзывы, блог,
видео, «о нас». Завести таблицу и раздел в закрытой части значит решить за
владельца бэкенда, как устроены заявки, поэтому я этого не делал.

Включается тремя шагами, работы примерно на полчаса.

1. Таблица:

```sql
CREATE TABLE `leads` (
    `id`         INT UNSIGNED NOT NULL AUTO_INCREMENT,
    `name`       VARCHAR(200) NOT NULL,
    `phone`      VARCHAR(50)  NOT NULL,
    `contact`    VARCHAR(200) NULL DEFAULT NULL,
    `message`    TEXT         NOT NULL,
    `created_at` TIMESTAMP    NOT NULL DEFAULT CURRENT_TIMESTAMP,
    PRIMARY KEY (`id`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_unicode_ci;
```

2. Контроллер, который принимает `POST` с `Content-Type: application/json`,
   проверяет поля через `App\Core\Validator` и пишет строку моделью. Тело
   запроса, которое шлёт форма:

```json
{ "name": "...", "phone": "...", "contact": "...", "message": "..." }
```

3. Маршрут `$router->post('/api/lead', [LeadController::class, 'store'])`
   и адрес обработчика в разметке, `app/Views/front/home.php`:

```html
<form class="form" data-form data-endpoint="/api/lead" novalidate>
```

Дальше по вкусу: список заявок в админке, письмо на почту, пересылка
в сообщения сообщества ВК методом `messages.send`. **Ключ доступа сообщества
должен лежать только на сервере** и на фронтенд не передаваться.

Пока этого нет, посетителю остаются телефон, почта и WhatsApp — они рядом
с формой и работают.

Чтобы посмотреть состояние ошибки без бэкенда, добавьте форме атрибут
`data-mock-fail="true"`.

## Лайтбокс

На весь сайт он один, в `public/assets/js/lightbox.js`. Его используют увеличение
фотографий услуг, полоса «О нас», галерея работ, раздел «Видео», сканы
благодарственных писем и иллюстрации в статьях.

Подключается к любому элементу через data-атрибуты:

```html
<button class="media-btn" type="button"
        data-lb-src="/img/big.jpg"
        data-lb-alt="описание для доступности"
        data-lb-title="Заголовок"
        data-lb-text="Описание под медиа"
        data-lb-group="works">
```

Вместо `data-lb-src` можно поставить `data-lb-video` (свой файл)
или `data-lb-embed` (внешний плеер). Видео и внешний плеер при закрытии
останавливаются, источник выгружается: звук за закрытым окном не играет.
Соседние кадры предзагружаются только для фотографий, видео заранее
не тянется.

`data-lb-group` объединяет снимки в галерею с листанием и счётчиком.
Без него открывается одиночное изображение.

Построен на `<dialog>`: фокус-трап, закрытие по Esc и возврат фокуса на
триггер работают средствами браузера. Листание стрелками, соседние кадры
предзагружаются, есть состояние загрузки и состояние ошибки.
Обработчик навешен делегированием, поэтому заработает и на контенте,
который в будущем приедет из админки.

Проверка шла в реальном Chromium на работающем PHP и MySQL, не на глаз.

**Связка админки и сайта**

  редактирования ведут под префикс

* 12 ширин экрана от 360 до 1920: горизонтального выноса нет нигде,

  через состояние отправки к состоянию успеха (успех пока имитация,
  см. раздел о заявках)
* Лайтбокс: открытие, счётчик `1 / 8`, листание стрелками влево и вправо,
  фокус при открытии на кнопке закрытия, закрытие по Esc, снятие блокировки

* Мобильное меню открывается и закрывается
* При `prefers-reduced-motion: reduce` не остаётся ни одного невидимого блока
* В консоли нет ошибок, ни одного запроса со статусом 400 и выше

## Известные ограничения

* **Благодарственные письма отредактированы.** Их четыре. В сканах закрыты
  банковские реквизиты контрагентов (расчётный и корсчёт, БИК, ИНН), а в письме
  «Уральской слободы» ещё и личный мобильный телефон названной по имени
  сотрудницы.
  На старом сайте всё это было открыто. Оригиналы без правок остались
  в архиве старого сайта, если понадобится вернуть.
* **Заявки с формы никуда не уходят.** Подробно выше, отдельным разделом.
  Это единственное место, где сайт не связан с бэкендом.
* **Виджет Яндекс Карт всегда светлый, поэтому карта грузится по нажатию.**
  Постоянно открытым он читался как белая врезка в тёмной странице, а по ТЗ
  секции не инвертируются. Теперь на месте карты тёмная заглушка с кнопкой
  «Показать карту», сторонний iframe приходит только когда его попросили,
  а адрес виден и без нажатия, в подписи под картой. Заглушка и карта одной
  высоты, блок при загрузке не прыгает. Полностью тёмная карта возможна
  через JS API Яндекса с ключом, если это понадобится.
* **Ссылки на картинки внутри статей абсолютные.** Так их кладёт редактор
  админки: `BlogController::uploadImage()` возвращает `asset($path)`. Это
  решение бэкенда, я его не менял. Практическое следствие: при смене домена
  мало поправить `base_url`, надо ещё заменить старый адрес в `posts.body`.
* **У видео нет постера.** В таблице `videos` нет поля под кадр-обложку,
  поэтому плиткой стоит сам ролик. Браузер тянет только заголовок файла,
  но это всё же запрос на каждый ролик в сетке. Поле `poster_path` сняло бы
  и это, и зависимость от того, какой кадр окажется на половине секунды.
* **Демо-витрина `/site` осталась на месте.** Она больше не нужна, но это
  чужой код и справочник по выводу данных, поэтому я её не удалял. Удаляется
  шестью строками в `app/routes.php` и каталогом `app/Views/site`.
